# Catalogue, niveaux de stock et consommation sur bons de travail

> Lisez les pièces, les types d'équipement, les vendeurs, les emplacements de stock, l'inventaire par emplacement et les pièces consommées sur les bons de travail avec l'API Équipes internes.

Autour du [flux d'achats](/partners-api/purchasing-flow) se trouvent les données de référence et de stock : ce que vous pouvez commander (pièces, types d'équipement), auprès de qui vous commandez (vendeurs), où cela vit (emplacements de stock et inventaire par emplacement), et où cela est allé (consommation sur bons de travail). Tout cela est en lecture seule via l'API Équipes internes.

Tous les exemples supposent :

```bash
export BASE="https://api.useopenwrench.com/api/external"
export KEY="<partner-api-key>"
export SECRET="<shared-secret>"
```

Chaque liste ci-dessous prend en charge les paramètres de pagination plus les filtres d'égalité sur les colonnes de l'entité (tout autre paramètre de requête, p. ex. `stockLocationId=42`), toujours restreint à votre entreprise.

## Catalogue

| Endpoint | Contenu |
| --- | --- |
| `GET /v1/partners/inventory/parts` (+`/{id}`) | Le catalogue de pièces : consommables et pièces de rechange. |
| `GET /v1/partners/inventory/equipment_types` (+`/{id}`) | Modèles d'équipement (articles sérialisés). |
| `GET /v1/partners/inventory/part_equipment_vendors` (+`/{id}`) | Vendeurs, utilisés comme `partEquipmentVendorId` sur les bons de commande. |

```bash
curl -H "X-API-KEY: $KEY" -H "OW-KEY: $SECRET" "$BASE/v1/partners/inventory/parts?limit=25"
curl -H "X-API-KEY: $KEY" -H "OW-KEY: $SECRET" "$BASE/v1/partners/inventory/part_equipment_vendors"
```

Synchronisez-les dans votre système d'achats en premier; chaque autre appel référence leurs ids.

## Emplacements de stock et inventaire

Les **emplacements de stock** sont les entrepôts, camions et réserves qui contiennent l'inventaire :

```bash
curl -H "X-API-KEY: $KEY" -H "OW-KEY: $SECRET" "$BASE/v1/partners/inventory/stock_locations"
curl -H "X-API-KEY: $KEY" -H "OW-KEY: $SECRET" "$BASE/v1/partners/inventory/stock_locations/7"
```

Deux types de fiches expriment ce qui est conservé où :

**Pièces par emplacement de stock** (`GET /v1/partners/inventory/parts_per_stock_locations`, +`/{id}`) : une fiche par pièce par emplacement — quantités en main, réservées et disponibles, emplacement de casier et coûts.

```bash
# Où la pièce 210 est-elle stockée ?
curl -H "X-API-KEY: $KEY" -H "OW-KEY: $SECRET" \
  "$BASE/v1/partners/inventory/parts_per_stock_locations?partId=210"

# Tout ce qui est en stock à l'emplacement 7
curl -H "X-API-KEY: $KEY" -H "OW-KEY: $SECRET" \
  "$BASE/v1/partners/inventory/parts_per_stock_locations?stockLocationId=7"
```

**Équipement par emplacement de stock** (`GET /v1/partners/inventory/equipment_per_stock_locations`, +`/{id}`) : une fiche par unité physique sérialisée — numéro de série, état et provenance. Ce sont les unités que les [réceptions avec numéros de série](/partners-api/purchasing-flow#4-record-receipts-as-goods-arrive) créent.

Les réceptions sont le chemin d'écriture dans le stock via cette API; le côté lecture ici est la façon dont vous réconciliez le stock OpenWrench avec votre ERP.

## Pièces et équipement utilisés sur les bons de travail

`GET /v1/partners/work_order/work_order_parts_equipments/{workOrderId}` liste les fiches de pièces et d'équipement consommées sur un bon de travail : le côté consommation du grand livre d'inventaire.

```bash
curl -H "X-API-KEY: $KEY" -H "OW-KEY: $SECRET" \
  "$BASE/v1/partners/work_order/work_order_parts_equipments/9001"
```

Les résultats sont paginés et acceptent les mêmes filtres d'égalité. Pour les clés partenaires dont l'entreprise fournisseur **n'est pas** une entreprise de techniciens internes, les objets `workOrder` et `location` embarqués reviennent masqués, avec les champs sensibles retirés.

## Modèle de réconciliation

Une réconciliation d'inventaire nocturne :

1. Extrayez `parts_per_stock_locations` par emplacement de stock et comparez les quantités avec votre ERP.
2. Expliquez les écarts : réceptions enregistrées ce jour-là (entrée par achats) moins `work_order_parts_equipments` pour les bons de travail terminés ce jour-là (sortie par consommation).
3. Enquêtez sur ce qui reste : habituellement une réception manquée, un retour non enregistré (réception négative) ou une consommation journalisée contre le mauvais bon de travail.
