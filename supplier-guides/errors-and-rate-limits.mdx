# Errors and rate limits

> How the API signals failure and throttling, and how to handle both

## Error envelope

```json theme={null}
{
  "message": "Human-readable message",
  "type": "NotFoundException",
  "status": "error",
  "traceId": "abc123def45"
}
```

Include the `traceId` when you contact support. It lets us find the exact request in our logs.

## Status codes

- `400` — bad input, bad filter, or permission denied.
- `401` — missing or invalid `X-API-KEY` / `OW-KEY`.
- `429` — rate limit exceeded.
- `5xx` — server error; retry with backoff.

## Rate limits

Every key is capped at **10 requests per 20-second window**. Beyond that you receive `429 Too Many Requests`.

Recommended handling:

1. Catch `429`.
2. Wait at least 20 seconds before retrying.
3. Space background jobs (e.g. full paginated exports) so they stay under the cap.
