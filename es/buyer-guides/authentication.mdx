# Autenticación

> Requisitos de cabeceras, alcance y gestión de claves para la Buyer API

Cada solicitud a la Buyer API debe llevar dos cabeceras:

- `X-API-KEY`: tu clave de la Buyer API, emitida por cada contacto comprador.
- `OW-KEY`: el secreto compartido de OpenWrench emitido junto con la clave.

Las solicitudes que no incluyan alguna de las dos cabeceras devuelven `401`.

```bash theme={null}
curl -H "X-API-KEY: <your-key>" -H "OW-KEY: <shared-secret>" \
  "https://api.useopenwrench.com/api/external/v1/buyer/ping"
```

## Alcance

Tu clave está limitada a un único contacto comprador, que se resuelve en una empresa. Cada endpoint de listado filtra los resultados automáticamente a ese alcance. No puedes ver órdenes de trabajo, activos ni facturas de otra empresa con tu clave.

Usa `GET /v1/buyer/me` para inspeccionar el contacto, la instalación y la empresa asociados a una clave.

## Rotación de claves

Para rotar una clave, solicita un nuevo par clave/secreto compartido a [support@useopenwrench.com](mailto:support@useopenwrench.com), despliega el nuevo par y luego pide a soporte que revoque el anterior. Las claves no caducan por sí solas.

## Claves de la Internal Teams API

La [Internal Teams API](/partners-api/introduction) usa una clave de API de partner separada. Una clave de comprador no se autenticará contra los endpoints `/v1/partners/` ni viceversa.
