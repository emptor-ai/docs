La Buyer API de OpenWrench da a los operadores de instalaciones acceso programático a todo lo que hay del lado del comprador en la plataforma. Puedes usarla para crear y hacer seguimiento de órdenes de trabajo, gestionar activos y ubicaciones, revisar cotizaciones y facturas, monitorear el mantenimiento preventivo y consultar tu red de proveedores.

## URL base

```text
https://api.useopenwrench.com/api/external
```

Todos los endpoints del comprador están bajo `/v1/buyer/`.

## Autenticación

Cada solicitud debe llevar **dos cabeceras**: `X-API-KEY` (tu clave de API, emitida por contacto de comprador) y `OW-KEY` (el secreto compartido de OpenWrench emitido junto a ella). La clave delimita automáticamente cada solicitud a tu empresa: solo verás tus propios datos. Las solicitudes a las que les falte cualquiera de las cabeceras devuelven `401`.

```bash
curl -H "X-API-KEY: <your-key>" -H "OW-KEY: <shared-secret>" \
  "https://api.useopenwrench.com/api/external/v1/buyer/ping"
```

Para obtener una clave de API y un secreto compartido, contacta a [support@useopenwrench.com](mailto:support@useopenwrench.com). Usa `GET /v1/buyer/me` para inspeccionar la identidad (contacto, instalación, empresa) detrás de tu clave.

Las claves no expiran por sí solas. Para rotar una, solicita a soporte un nuevo par clave/secreto compartido, despliega el nuevo par y luego pide a soporte que revoque el antiguo.

<Note>
La sección **Internal Teams API**, más abajo en esta pestaña, usa una **clave de API de partner distinta**: tu clave de comprador no autenticará contra esos endpoints `/v1/partners/`. Consulta la [introducción a la Internal Teams API](/es/partners-api/introduction) para más detalles.
</Note>

## Límites de tasa

10 solicitudes por ventana de 20 segundos por clave. Al superarlo recibirás `429 Too Many Requests`: espera al menos 20 segundos antes de reintentar y espacia los trabajos en segundo plano (como exportaciones paginadas completas) para que se mantengan por debajo del límite.

## Mantener las órdenes de trabajo sincronizadas

Si tu integración replica las órdenes de trabajo en otro sistema (una herramienta de tickets, un ERP, un data warehouse), constrúyela sobre push, no sobre sondeo:

1. Registra un endpoint de [webhook](/es/buyer-api/webhooks). OpenWrench envía los eventos `workorder.create`, `workorder.status_update` y `workorder.new_note` a medida que ocurren.
2. En cada evento, obtén esa única orden de trabajo con `GET /v1/buyer/work_order/work_orders/{id}`.
3. Usa `GET /v1/buyer/work_order/work_orders` para consultas puntuales, la carga inicial única y la conciliación ocasional, con un filtro estrecho y una página pequeña.

No sondees el endpoint de listado según un cronograma para descubrir órdenes de trabajo nuevas o cambiadas. Es la lectura más costosa de la API, es lenta en cuentas grandes y compite con tu trabajo real por el límite de tasa. Consulta [Órdenes de trabajo](/es/buyer-api/work-orders#listar-filtrar-y-contar) para los detalles.

## Envoltura de respuesta

Respuestas de una sola entidad:

```json
{ "type": "WorkOrder", "data": { "...": "..." }, "status": "ok" }
```

Las respuestas de listado añaden un `count` total:

```json
{ "type": "WorkOrder", "data": [ "..." ], "count": 42, "status": "ok" }
```

Errores:

```json
{ "message": "Human-readable message", "type": "NotFoundException", "status": "error", "traceId": "abc123def45" }
```

`401` significa clave faltante o inválida; `400` cubre entrada inválida, filtros incorrectos y denegaciones de permisos; `429` es el límite de tasa.

## Paginación y filtrado

Los endpoints de listado aceptan `offset`, `limit` (por defecto 10, máx. 25), `sort_by` y `order` (`asc` | `desc`). Los parámetros de consulta adicionales se tratan como filtros. Cada endpoint admite su propio conjunto de claves de filtro, y las claves que no reconoce se ignoran en lugar de rechazarse. Los filtros de varios valores usan una clave en plural con valores separados por comas (`statuses=Unassigned,PendingApproval`). Para órdenes de trabajo, consulta la [referencia de filtros](/es/buyer-api/work-orders#referencia-de-filtros).

## Formatos de fecha

La mayoría de las marcas de tiempo son cadenas ISO 8601 con offset (por ejemplo `2026-08-14T13:05:22.000-07:00`); algunos campos de marca de tiempo de base de datos se serializan como `yyyy-MM-dd HH:mm:ss.S`. Las fechas simples son `yyyy-MM-dd`. Cuando envíes fecha-hora, usa ISO 8601.

Los filtros de fecha de los listados de facturas, propuestas y órdenes de trabajo son la excepción. Usan `MM/dd/yyyy HH:mm:ss`, una hora local de reloj sin offset, por ejemplo `10/09/2026 00:00:00`:

- **Zona horaria.** Pasa el parámetro de consulta opcional `timezone` para establecer la zona en la que se interpretan los valores. Usa un nombre de zona IANA, como `America/Chicago`, `America/New_York` o `UTC`. Los nombres distinguen mayúsculas y minúsculas. Sin `timezone`, los valores se interpretan en UTC.
- **Zonas rechazadas.** Los offsets fijos (`-05:00`, `GMT-5`, `Z`, `Etc/GMT+5`), las abreviaturas (`CST`) y los nombres desconocidos devuelven `400`.
- **Sin offset en el valor.** OpenWrench ignora un offset como `-05:00` al final de un valor de filtro. Usa `timezone` en su lugar.
- **Los valores mal formados devuelven `400`.** Un valor que no coincide con el formato devuelve `400`, por ejemplo `Invalid markedPaidAtStartDate. Expected format MM/dd/yyyy HH:mm:ss`. Eso incluye valores ISO 8601 (`2026-10-09T00:00:00`), fechas sin hora (`10/09/2026`) y valores formados solo por espacios. Un valor vacío se sigue leyendo como 1 de enero de 1970.
- **Extremos finales.** Las fechas finales de facturas y propuestas cubren todo el día final: OpenWrench reemplaza la hora por 23:59:59 en esa fecha en `timezone`. Las fechas finales de órdenes de trabajo son exactas, así que envía `23:59:59` para incluir el día completo.
- **Horario de verano.** Una hora dentro de la hora omitida en un cambio de adelanto de reloj se desplaza hacia delante la duración del salto. Una hora dentro de la hora repetida en un cambio de atraso de reloj se refiere a la ocurrencia en horario estándar, que es la segunda.

Por ejemplo, esta solicitud devuelve las facturas marcadas como pagadas el 9 de octubre de 2026, en hora central:

```bash
curl -H "X-API-KEY: $KEY" -H "OW-KEY: $SECRET" \
  "$BASE/v1/buyer/invoice/invoices?markedPaidAtStartDate=10/09/2026%2000:00:00&markedPaidAtEndDate=10/09/2026%2000:00:00&timezone=America/Chicago"
```

Para los filtros de cada listado, consulta las reglas de valores de filtro de [órdenes de trabajo](/es/buyer-api/work-orders#reglas-de-valores-de-filtro), [facturas](/es/buyer-api/invoices#reglas-de-valores-de-filtro) y [propuestas](/es/buyer-api/quotes-and-proposals#referencia-de-filtros).
