# Authentication

> Header requirements, scoping, and key handling for the Buyer API

Every Buyer API request must carry two headers:

- `X-API-KEY` — your Buyer API key, issued per buyer contact.
- `OW-KEY` — the OpenWrench shared secret issued alongside the key.

Requests missing either header return `401`.

```bash theme={null}
curl -H "X-API-KEY: <your-key>" -H "OW-KEY: <shared-secret>" \
  "https://api.useopenwrench.com/api/external/v1/buyer/ping"
```

## Scoping

Your key is scoped to a single buyer contact, which resolves to one company. Every list endpoint filters results to that scope automatically. You cannot see another company's work orders, assets, or invoices with your key.

Use `GET /v1/buyer/me` to inspect the contact, facility, and company behind a key.

## Key rotation

To rotate a key, request a new key/shared-secret pair from [support@useopenwrench.com](mailto:support@useopenwrench.com), deploy the new pair, then ask support to revoke the old one. Keys do not expire on their own.

## Internal Teams API keys

The [Internal Teams API](/partners-api/introduction) uses a separate partner API key. A Buyer key will not authenticate against `/v1/partners/` endpoints and vice versa.
