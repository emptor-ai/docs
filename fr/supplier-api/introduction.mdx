L'API Fournisseur OpenWrench donne aux prestataires de services un accès programmatique à leur côté de la plateforme : réception et mise à jour des bons de travail, planification et documentation des visites de service, soumission des propositions et factures, extraction des données de temps des techniciens WrenchMode, et gestion des achats et de l'inventaire.

## URL de base

```text
https://api.useopenwrench.com/api/external
```

Tous les endpoints fournisseur se trouvent sous `/v1/supplier/`.

## Authentification

Chaque requête doit contenir **deux en-têtes** : `X-API-KEY` (votre clé d'API, émise par contact fournisseur) et `OW-KEY` (le secret partagé OpenWrench émis en même temps). La clé restreint automatiquement chaque requête à votre établissement. Vous ne voyez jamais que les bons de travail, factures et données qui vous appartiennent. Les requêtes auxquelles il manque l'un des deux en-têtes renvoient `401`.

```bash
curl -H "X-API-KEY: <your-key>" -H "OW-KEY: <shared-secret>" \
  "https://api.useopenwrench.com/api/external/v1/supplier/ping"
```

Pour obtenir une clé d'API et un secret partagé, contactez [support@useopenwrench.com](mailto:support@useopenwrench.com).

Les clés n'expirent pas d'elles-mêmes. Pour en faire tourner une, demandez au support une nouvelle paire clé/secret partagé, déployez la nouvelle paire, puis demandez au support de révoquer l'ancienne.

## Limites de débit

10 requêtes par fenêtre de 20 secondes par clé. Au-delà, vous recevrez `429 Too Many Requests` : attendez au moins 20 secondes avant de réessayer, et espacez les tâches d'arrière-plan (par exemple les exports paginés complets) pour qu'elles restent sous la limite.

## Enveloppe de réponse

Réponses pour une entité unique :

```json
{ "type": "WorkOrder", "data": { "...": "..." }, "status": "ok" }
```

Les réponses de liste ajoutent un `count` total :

```json
{ "type": "WorkOrder", "data": [ "..." ], "count": 42, "status": "ok" }
```

Erreurs :

```json
{ "message": "Human-readable message", "type": "NotFoundException", "status": "error", "traceId": "abc123def45" }
```

`401` signifie des identifiants manquants ou invalides ; `400` couvre les données saisies erronées, les filtres invalides et les refus de permission ; `429` correspond à la limite de débit.

## Pagination et filtrage

Les endpoints de liste acceptent `offset`, `limit` (par défaut 10, max 25), `sort_by` et `order` (`asc` | `desc`). Les paramètres de requête supplémentaires sont traités comme des filtres de champ. Passez un nom de champ avec une valeur (séparez plusieurs valeurs par des virgules) pour filtrer le jeu de résultats. La page de référence de chaque endpoint énumère ses filtres notables.

## Formats de date

La plupart des horodatages sont des chaînes ISO 8601 avec décalage (par exemple `2026-08-14T13:05:22.000-07:00`) ; certains champs d'horodatage de base de données sont sérialisés sous la forme `yyyy-MM-dd HH:mm:ss.S`. Les dates simples sont au format `yyyy-MM-dd`. Lorsque vous envoyez des dates-heure, utilisez ISO 8601.

## Données de temps des techniciens

Les endpoints WrenchMode exposent le temps de travail et de conduite par technicien : `GET /v1/supplier/wrench_mode/events/analytics/{fromDate}/{toDate}` retourne un cumul conduite/travail/total par technicien (fenêtre plafonnée à 1 mois), et `GET /v1/supplier/wrench_mode/events` retourne le journal d'événements brut sous-jacent. Les extensions de visite de service (`/with_work_logs`, `/with_tech_details`) offrent le récit par visite.
