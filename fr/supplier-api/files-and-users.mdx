# Stockage de fichiers et provisionnement d'utilisateurs dans l'API Fournisseur

> Téléversez et téléchargez des fichiers pour les pièces jointes et provisionnez les utilisateurs et techniciens fournisseurs, y compris l'accès aux emplacements de stock et les certifications EPA.

Deux surfaces d'appui dont la plupart des intégrations fournisseur ont besoin : le stockage de fichiers derrière chaque champ de pièce jointe, et le provisionnement d'utilisateurs par programmation pour l'intégration des techniciens.

Tous les exemples supposent :

```bash
export BASE="https://api.useopenwrench.com/api/external"
export KEY="<your-api-key>"
export SECRET="<shared-secret>"
```

## Fichiers

**Téléversez** avec `POST /v1/supplier/file/upload` : formulaire multipart, une seule partie nommée `file`, max **512 Mo**.

```bash
curl -X POST "$BASE/v1/supplier/file/upload" \
  -H "X-API-KEY: $KEY" -H "OW-KEY: $SECRET" \
  -F "file=@before.jpg"
```

La réponse (type d'enveloppe `FileManager`) est un enregistrement `FileDetails` : `{ "fileName": "before.jpg", "fileId": "a1b2c3d4e5" }`. Les caractères non ASCII sont supprimés du nom de fichier ; un échec de stockage retourne `500`.

Utilisez l'objet retourné tel quel dans les champs de pièces jointes : [pièces jointes fournisseur](/supplier-api/work-orders#keep-the-buyer-informed) sur les bons de travail, `attachments` sur les propositions et factures, et images de pointage d'entrée/sortie. Les PDF de factures disposent de leur propre [endpoint de téléversement et publication](/supplier-api/quotes-and-invoicing#upload-the-pdf-and-publish).

**Téléchargez** avec `GET /v1/supplier/file/download/{id}/{name}`, qui diffuse les octets stockés en pièce jointe. `{id}` est le `fileId` ; `{name}` est le nom sous lequel le servir. Utilisez-le pour extraire les documents fournis par l'acheteur depuis `buyerAttachments`. Les échecs de téléchargement renvoient `400`.

## Provisionner des utilisateurs fournisseurs

`POST /v1/supplier/user/provision` crée un contact fournisseur sous votre entreprise, éventuellement avec une connexion active. Usage typique : intégrer des techniciens depuis votre système RH.

```bash
curl -X POST "$BASE/v1/supplier/user/provision" \
  -H "X-API-KEY: $KEY" -H "OW-KEY: $SECRET" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "sam.tech@supplier.com",
    "nameGiven": "Sam",
    "nameFamily": "Ortiz",
    "roles": ["SUPPLIER_TECH"],
    "title": "Refrigeration Technician",
    "epaCertificationType": "Type II",
    "epaCertificationNumber": "EPA-882913",
    "stockLocationIds": [7]
  }'
```

Règles imposées par l'endpoint :

- `email` (mis en minuscules et rogné), `nameGiven`, `nameFamily` et un tableau `roles` non vide sont requis. Les noms de rôles sont mis en correspondance sans distinction de casse, et **les rôles d'administrateur ou de super-administrateur sont refusés avec `403`**.
- Les rôles `SUPPLIER_TECH` reçoivent en plus un enregistrement de technicien de terrain, ce qui rend l'utilisateur planifiable sur les visites de service et visible dans WrenchMode.
- Le `facilityId` cible est par défaut celui de votre clé et doit appartenir à la même entreprise fournisseur (`403` sinon).
- Un compte ou contact existant pour l'adresse courriel est un conflit `400`.
- **Création de connexion.** Sans `password`, l'utilisateur reçoit un courriel d'invitation à s'inscrire. Avec un mot de passe, le compte est créé actif immédiatement ; ajoutez `passwordResetRequired` pour forcer un changement à la première connexion.
- **Accès aux emplacements** : `hasAccessToAllLocations`, ou `locationIds`/`brandIds` explicites (ignorés lorsque l'indicateur tous emplacements est vrai).
- **Accès aux emplacements de stock** : `hasAccessToAllStockLocations` et `canManageAllStockLocations` sont par défaut à faux et sont **forcés à faux dès que `stockLocationIds` n'est pas vide** ; les identifiants explicites l'emportent.
- Qualifications EPA 608 : `epaCertificationType` est validé par rapport aux classes reconnues ; `epaCertificationNumber` est en texte libre.

Le contact créé est retourné dans l'enveloppe standard.
